# Campus Link iOS（Expo）

画面は、ようこそ・ログイン・新規登録、オンボーディング・写真・在学・年齢確認の提出・マイページ、探す・絞込み・プロフィールの詳細・いいね・トーク、公開範囲・ブロックした人・通報の状態・休止・退会・すべての端末からのログアウト、プロフィールの編集（任意の目的と1つの自己紹介）。探すの一覧は1つ。下のナビは「探す」「いいね」「トーク」「マイページ」の4つ。ようこその文は「同じ学生どうしで、つながろう。」。ログインと登録は、Web版と同じ判定（回数制限、失敗の時間、退会済みの扱い）を通るアプリ用のAPI（`/api/mobile/auth/signin`・`signup`）を呼ぶ。セッションはiPhoneのKeychain（`expo-secure-store`、この端末だけ、最初のロック解除の後）にだけ保存する。

依存はこのフォルダの `package.json` だけで、ルートのWeb版とは別。Web版から使うのは、`import` のない `src/lib` の4つのファイルだけ（`src/shared.ts`）：`auth-validation.ts`（ログイン・登録の検証と文言）、`onboarding-rules.ts`（オンボーディングの検証と目的の符号・表示）、`verification-reasons.ts`（却下・取消しの理由の文）、`photo-downscale.ts`（4 MiBの上限と1600 pxの縮小の大きさだけ）。画面の文言のうちWeb版のコンポーネントにあるものは `src/messages.ts` に写し、`tests/messages.test.ts` でWeb版と同じ文字列であることを確かめる。規約とプライバシーポリシーは、アプリ内のブラウザの `expo-web-browser`（SDK 58が指定する版、58.0.8）で開く。

ログイン後の画面は、Web版と同じRPCを利用者のJWTでそのまま呼ぶ（`src/rpc.ts` の名前の一覧の外は呼ばない）。写真の取込み・表示・削除だけは、アプリ用のAPI（`/api/mobile/photos`、Bearerだけ）を通る。

- 写真はiPhoneの写真ライブラリから1枚選び、端末で1600 px以内に縮小してWebP（品質0.85）にし、`photo.webp` の名前で送る。HEICもここでWebPになる。新しいファイルにEXIFや位置の情報は残らない。サーバーはさらに取り直し（再エンコード）をする。縮小の後も4 MiBを超える画像は送らない。
- 表示した写真は `expo-image` のメモリのcacheだけに置き（`cachePolicy="memory"`、ディスクのcacheを使わない）、ログアウトとブロックの後にメモリのcacheも消す。
- 見えない相手・存在しないプロフィール・形の違うIDは、同じ「このプロフィールは表示できません」になる（P5）。会話も同じく「この会話は表示できません」。
- 運営が非表示にした発言は、DBが置き換えた本文を使わず、Web版と同じ「この発言は運営により非表示になりました。」を出す。通報のボタンも出さない。
- **ログアウト**：「ログアウト」はこの端末だけ（`signOut({ scope: "local" })`）でようこそへ。「すべての端末からログアウト」は `signOut({ scope: "global" })`。Authが失敗を返すか例外になったときは、成功と同じに見せず、ログインの画面にWeb版の `/login?error=signout` と同じ文（「ほかの端末のログアウトを確かめられませんでした。…」）を出す。どちらの場合も、この端末のセッションは消す：失敗のときは `local` でも終わらせ、最後にKeychainの値を直接消し、写真のメモリのcacheも消す。Authの答えの文は出さず、ログにも書かない。
- **退会**：Web版と同じ確認の言葉「退会する」が一字一句同じになるまで「退会する」のボタンは押せない（前後の空白も不可）。`request_account_deletion` が通ると、その場で「退会の手続きが完了しました」を出し、Web版の `deleteAccount` と同じくすべての端末からログアウトし、Keychainの値と写真のcacheを消す。退会済みのアカウントは、どの画面の振り分け（`my_account`）とログインのAPIでも断られるので、Web版と同じく、この後のglobalのログアウトの失敗は画面に出さない。断られた退会（`forbidden` など）はWeb版と同じ文を出し、セッションはそのまま。
- **休止**：休止中は探す・いいね・トークに表示されず、自分も使えない（Web版と同じ注意書き）。マイページの「アカウントは休止中です。」の横に「再開する」。停止（suspended）のアカウントには切替えを出さない。
- **規約とプライバシーポリシー**：Web版の自分のサイトのページ（`/terms`・`/privacy`）だけを、アプリ内のブラウザ（`expo-web-browser`、SFSafariViewController）で開く。WebViewは使わない。
- ブロック中のユーザーの画面は、相手のIDを画面にもログにも出さない（RPCから受け取るIDは解除にだけ使う）。
- **Realtime**：アプリは自分のsupabase-jsのセッション（Keychain）でRealtimeにつなぐ。supabase-jsが、接続のときとトークンの更新のたびにaccess tokenをRealtimeに渡す。Web版の `/api/realtime-token` はHttpOnlyのcookieを読めないブラウザのためのもので、アプリには要らない（Bearer版のrouteも作らない）。届いた変更の中身は使わず、RPCで読み直す（判定はRLSとRPC）。トーク一覧は1秒に1回まで、トークの画面は接続の回復の後とアプリが前面に戻ったときにも読み直す。

## iPhoneのExpo Goで動かす

要るもの：このrepoを置いた開発用のPC（手順はWindowsの例）、iPhone、同じWi-Fi。Expo GoとAppleの年会費は要らない（Expo GoはApp Storeの無料のアプリ）。

1. **iPhone**：App Storeから「Expo Go」を入れる。
2. **Webのサーバー（PC）**：repoの最上位の `.env.local` が `CAMPUS_LINK_BACKEND=supabase` と開発用のSupabaseのプロジェクトの値になっていることを確かめ、`npm run dev` で起動する（ポート3000）。
   - デモのモード（`CAMPUS_LINK_BACKEND` が `supabase` でない）では、アプリのAPIは404を返し、アプリは「現在ご利用いただけません」と出す。
   - 初回にWindowsのファイアウォールがNode.jsの通信を尋ねたら、「プライベート ネットワーク」だけを許可する。
   - アプリ内のブラウザ（規約・プライバシーポリシー）やiPhoneのSafariで開いたWeb版のページを動かすには、PCのLANのIPv4アドレス（`ipconfig`）を環境変数 `CAMPUS_LINK_DEV_ORIGINS` に入れて起動する。入れないと、Nextが開発用のファイル（`/_next/hmr` など）をそのアドレスから読ませず、ボタンなどが動かない。複数ならカンマで区切る。`.env.local` やGitには書かず、起動のときだけ指定する。開発のサーバーだけで使われ、本番には効かない。
     ```powershell
     $env:CAMPUS_LINK_DEV_ORIGINS = "<PCのIPv4アドレス>"; npm run dev
     ```
3. **アプリの設定（PC）**：
   ```sh
   cd mobile
   npm ci
   copy .env.example .env.local
   ```
   `mobile/.env.local` に、Web版の `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` と同じ値を `EXPO_PUBLIC_SUPABASE_URL` と `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` に書く。どちらも公開の値。service roleのキーは書かない。`.env.local` はGitに入らない。
   - `EXPO_PUBLIC_API_BASE_URL` は空のままでよい。空なら、Expo GoがつないだPCのLANのアドレスの3000番（例 `http://192.168.1.23:3000`）を使う。つながらないときは、`ipconfig` のIPv4アドレスで `http://<そのアドレス>:3000` と書く。
4. **起動（PC）**：`mobile` で `npx expo start`。端末にQRコードが出る。
5. **iPhone**：カメラのアプリでQRコードを読み、「Expo Goで開く」を押す。
   - 開かないときは、PCとiPhoneが同じWi-Fiか、`npx expo start --tunnel` を試す（tunnelは追加のパッケージを求めることがある。その場合は入れずに止める）。

### 試す流れ

1. 「新規登録」でアドレスとパスワードを入れる。既存のアドレスでも同じ「確認メールを送信しました」が出る。
2. 届いたメールのリンクをiPhoneのSafariで開き、Web版で確認を終える（確認のリンクはWeb版のまま）。
3. アプリに戻って「ログイン」。初めてならオンボーディングが開く。アプリを閉じて開き直しても、Keychainのセッションでログインのまま。
4. **オンボーディング**：表示名・性別・生年月日（年・月・日）・「18歳以上です」→ 学校・学科・クラス → 写真の説明 → 目的（任意・いくつでも）と自己紹介（任意） → 確認 →「プロフィールを保存」。
   - 空のまま「次へ」を押すと、Web版と同じ文言が出る。18歳未満の生年月日（例 2015年1月1日）は先へ進めない。
   - 所属の一覧は開発用のSupabaseのプロジェクトの表の値。表が空なら、Web版の管理画面で架空の学校・学科・クラスを作る。
5. **写真**：「写真を追加」でカメラロールの写真を選ぶ。初回は写真ライブラリの許可を尋ねられることがある（選んだ1枚だけを渡す方を選んでよい）。
   - 縮小と送信の間はボタンが押せない。登録されると写真が表示される。「前へ」「後へ」で並べ替え、1枚目がメイン。
   - 7枚目は「写真は6枚までです。」、短い間に何度も送ると「しばらくしてから再度お試しください。」。
6. 写真が1枚以上になると「プロフィールを完成」が押せる。完成すると「在学・年齢確認へ」と「マイページへ」が出る。
7. **在学・年齢確認**：架空のサンプル資料を1〜3点選んで「提出」。状態が「提出済み」になり、「取り下げ」ができる。実在の資料は扱わない。何も選ばずに「提出」すると「架空のサンプル資料を1〜3点選んでください。」。
8. **マイページ**：表示名、年齢確認・在学確認の状態、写真の管理（完成した後は最後の1枚は削除できない）、プロフィールを編集（目的と自己紹介）・在学・年齢確認・利用規約・プライバシーポリシーへの入口、「ログアウト」。
9. 「ログアウト」で、この端末のセッションとKeychainの値、写真のメモリのcacheが消え、ようこそに戻る。
10. PCのWeb版で同じアカウントにログインし、アプリで作ったプロフィールと写真がWeb版にも出ることを確かめる。

### 2人での試し（iPhoneのアプリとPCのWeb版）

2人目の利用者は、PCのブラウザのWeb版でつくる（どちらも開発用のプロジェクトの架空のデータ）。

1. **準備**：アカウントを2つ用意する（A＝iPhoneのアプリ、B＝PCのWeb版）。どちらもオンボーディング（写真1枚以上）と在学・年齢確認を済ませ、Web版の管理画面で両方の確認を承認する。確認が済むまで、探すは「在学・年齢確認が終わると、プロフィールを探せます。」を出す。
2. **探す（A）**：ログインすると探すが開く。一覧は1つで、カードに目的が小さく出る。「検索条件」で年齢（例 下限30・上限20は「下限は上限以下にしてください。」）・性別・学校を選び、「この条件で探す」。条件の札と「条件をクリア」が出る。
3. **詳細（A）**：Bの「プロフィールを見る」。写真がすべて出る。BがWeb版の公開範囲でAの所属（学校・学科・クラス）を非表示にすると、同じ画面が「このプロフィールは表示できません」になる（存在しないIDと同じ）。
4. **いいね（A→B）**：詳細かカードの「いいね」→「いいねしました。」と「いいね済み」。「取り消す」で「いいねを取り消しました。」。いいねした人は探すに出なくなり、「いいね」の「いいねした」に出る。
5. **マッチ（B、PC）**：Web版の「いいね」の「いいねされた」で「いいねを返す」→「マッチしました。トークで話せます。」。逆向き（BがAにいいねし、Aがアプリの「いいねされた」か詳細の「いいねを返す」）も試す。マッチの後に「トークを開く」が出る。
6. **トーク**：Aのアプリの「トーク」に会話が出る。PCのWeb版からBが送ると、アプリの一覧の最新の文と「未読」がすぐ変わり、会話の画面にも発言がすぐ出る。アプリから送ると、PCのWeb版にもすぐ出る。Wi-Fiを切って戻す、アプリをバックグラウンドから戻すと、その間の発言も読み直される。
7. **非表示**：Web版の管理画面で、通報された発言を非表示にする。アプリの会話の画面に「この発言は運営により非表示になりました。」が出る。
8. **ブロック**：Bが（Web版で）Aをブロックした直後に、アプリの会話の画面が「この会話は表示できません」になり、新しい発言が届かなくなる（hostedの環境での配信の止まり方はまだ確かめていない）。アプリの「ブロック・通報」からAがBをブロックしても同じ。ブロックの後は、探す・いいね・トークのどこにも相手が出ず、2人のいいねも消える。
9. **通報**：プロフィール（詳細といいねの各行）・会話・相手の発言の「通報」から、理由と詳細（1000文字まで）を送る。「通報を受け付けました。」。短い間に何度も送ると「しばらくしてから再度お試しください。」。

### 設定と安全

1. **公開範囲（A）**：マイページの「公開範囲設定」。「同じ学校に表示しない」を入れて「保存する」→「保存しました。」。Bが同じ学校なら、Bの探す・詳細からAが消える（Web版のBの画面で確かめる）。「非表示対象を管理」で学校・学科・クラスを個別に追加・解除できる（合わせて50件まで）。
2. **ブロック中のユーザー（A）**：前の手順でブロックした相手が名前と日付で出る。「ブロックを解除」→ 確認 →「ブロックを解除しました。」→「閉じる」で一覧から消える。消えたいいねや終了したつながりは戻らない。「通報の履歴」に前の手順で送った通報の日付と状態（受付済み・確認中・対応済み・対応なし）が出る。
3. **休止（A）**：「アカウント」→「休止する」→「休止しました。」。Bの探す・いいね・トークからAが消える。マイページの「再開する」から戻し、「再開しました。」。
4. **すべての端末からログアウト（A）**：PCのWeb版にもAでログインしておく。アプリのマイページ（またはアカウント）で「すべての端末からログアウト」→ ようこそに戻る。PCのWeb版で画面を移ると、ログインし直しになる（リフレッシュトークンが無効になる。アクセストークンの期限までは残りうる）。Wi-Fiを切った状態で押すと、ログインの画面に「ほかの端末のログアウトを確かめられませんでした。…」が出て、この端末はログアウトしている。
5. **退会（試し用の架空のアカウントだけで）**：「アカウント」→「退会の手続きへ」→「退会する」と入力 →「退会する」。「退会の手続きが完了しました」「ログアウトしました。」が出る。同じアドレスでログインしても入れない。本文の「プライバシーポリシー」はアプリ内のブラウザで開く。

## 範囲の外

プッシュ通知（入れるときは、ログアウトの前にプッシュのtokenの登録を消す処理も加える）、支払い、Appleの開発者アカウント、EAS Buildは、今後の課題。カメラでの撮影は使わない（写真ライブラリだけ）。
